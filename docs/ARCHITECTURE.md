# 編集と保存の境界

初期プロトタイプの設計です。Swift・実機・Filesプロバイダでの動作を保証するものではありません。

## 本文と操作の識別

UITextViewだけが編集中の本文、marked range、選択、Undoを所有します。SwiftUIとCoreへ渡す本文は保存・復旧用snapshotです。文書UUID、runtime session、本文revision、永続metadata epoch、操作tokenを照合し、古い入力通知や保存応答で現本文を差し戻しません。

明示保存は固定snapshotの下書き保護が成功してから書き込みます。処理中の追記は新revisionとして保護します。通常の自動保護は一度に一つのsnapshotを待ち、ACK後に新しい入力があれば最新の版を保護します。OS停止前の未ACK入力まで必ず保護できるとは約束しません。

## 保存先と結果不明

保存先はopaque UUIDと全バイトSHA-256・サイズで識別します。新規の検証用保存先では同名を拒否します。既存保存では読込に失敗した状態を上書き許可にしません。書込み意図も端末に記録し、応答断や再起動後は結果不明として自動再送を停止します。

対応形式はUTF-8、BOM付きUTF-8、BOM付きUTF-16 LE/BEです。復号後の再符号化が元バイトと一致しない入力は拒否します。新規文書はUTF-8/CRLF、既存文書は原文の文字コードと改行を保持します。

Files adapterは既定無効です。Document Pickerで既存文書をin-placeで開き、security scope、bookmark、物理resource/volume identity、NSFileCoordinator、NSFilePresenterを使うソースを用意しています。安定identityが得られない場合や、別アプリのatomic置換でidentityが変わった場合は拒否し、再選択を要求します。新規・別名保存は未対応です。

Filesの調整は、端末へ届いていない他端末の変更まで検出する保証ではありません。書込み受付とDriveサーバーへの反映完了は区別します。直接Drive APIを採用する場合は、OAuth、server file ID、条件付き更新、通信断後の照合を別に設計する必要があります。現実装はOAuthやGoogle APIを使用しません。

## 比較履歴と容量

再読込ではbase/local/remoteの三原文を保持します。比較時だけ改行をLFに揃え、独立変更を候補にし、競合は手動確認へ回します。確認中に外部が再更新した場合も、基準を明示して新三原文を保護します。候補はnative編集コマンドを通し、一回のUndoで戻せる形で適用します。

比較履歴は原文を黙って切り捨てません。一覧はmetadataだけを取得し、選んだ一件の原文を遅延取得します。明示削除には確認文字、表示epoch、現在本文が保存済みであること、下書き保護成功を要求します。未保存・競合・結果不明の状態では削除しません。提案JSONの保存成功までメモリの履歴も残します。

容量判定は単一JSONの実バイト数を使います。既定の保管枠256MiB、単一JSON上限64MiB、実空き容量の留保128MiB。旧JSONと新JSONが共存するピークを要求し、容量不足時に旧記録を先に削除しません。破損・一時ファイルも数え、空き容量不明は停止します。既に保管枠を超えた場合、明示削除にも原子置換の余地が必要です。

置換の既定上限は入力・出力400万UTF-16単位、10万一致、UTF-8上限20MiB、推定peak128MiBです。部分適用はしません。全文JSONコピー、Undo、長いsessionのtoken増加による実メモリ負荷は未計測です。
